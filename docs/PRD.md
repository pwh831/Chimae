# PRD — 초기·중기 치매 환자 맞춤형 회상 게임

문서 버전 0.1 / 2026.09.01
2026 C.O.D.E. 트랙2(성장 — 예비창업 실습) 출품 기획

---

## 1. 개요

### 1.1 한 줄 정의
가족·요양보호사가 입력한 환자의 생애 정보를 바탕으로 AI가 그 사람만의 회상 활동을 만들고, 손자녀와 메시지를 주고받으며, 같은 요양원 어르신들과 공동 목표를 채워가는 회상 게임.

### 1.2 서비스 위치
**치료·진단이 아닌 정서적 안정과 소통 지원 서비스.**

"치매 치료", "인지 기능 향상"을 표방하면 의료기기 규제 영역에 진입한다. 본 서비스는 요양시설에서 이미 운영 중인 회상 프로그램과 같은 웰니스 영역에 머문다. 모든 대외 문구는 아래 원칙을 따른다.

| 쓰지 않는 표현 | 대체 표현 |
| --- | --- |
| 치매를 치료한다 | 정서적 안정과 소통을 돕는다 |
| 인지 기능을 향상시킨다 | 인지 활동을 꾸준히 이어가도록 돕는다 |
| 상태를 진단·판정한다 | 활동 기록을 가족과 공유한다 |

### 1.3 해결하려는 문제
회상 활동은 치매 환자의 정서적 안정에 도움이 되며 요양시설에서 널리 운영되고 있다. 그러나 실제 현장에서는 지속되기 어렵다.

- **가족의 물리적 거리** — 멀리 살거나 시설에 계시면 매일 함께 앉을 수 없다
- **돌봄 가족의 소진** — 같은 질문과 같은 이야기가 반복된다. 가족은 지치고, 짜증이 나고, 이후 죄책감을 느낀다
- **무엇을 물어야 할지 모름** — 마주 앉아도 어떤 소재가 반응이 좋은지 알 수 없다
- **대화가 남지 않음** — 나눈 이야기가 그 자리에서 사라져 다음 만남으로 이어지지 않는다
- **시설의 인력 한계** — 요양보호사가 여러 명을 돌보며 매일 1:1 회상 활동을 하기는 어렵다

### 1.4 핵심 프레이밍
> **가족을 대신하지 않는다. 가족이 없는 시간을 채우고, 만났을 때 더 잘 이야기하게 돕는다.**

## 2. 대상 사용자

### 2.1 1차 사용자 — 초기·중기 치매 환자
- 혼자 조작하는 것을 전제로 설계
- 중증은 범위에서 제외 (언어 소통 자체가 어려워 다른 접근이 필요)
- 태블릿 상시 거치, 큰 버튼 하나로 시작하는 형태를 상정

### 2.2 2차 사용자 — 소재 입력자
- **가족(주로 자녀·손자녀)**: 가정 돌봄 상황
- **요양보호사**: 시설 입소 상황
- 두 경로를 모두 열어둔다. 가정에서 시설로 옮겨가는 경우가 흔하며, 이때 축적된 생애 정보가 따라가면 시설의 초기 라포 형성이 빨라진다

### 2.3 지불자
실사용자와 지불자가 분리된 구조. 시설(B2B) 또는 자녀(구독).

---

## 3. 핵심 세션 흐름

```
태블릿 알림
  ↓
손자녀가 낸 문제 풀기
  ↓
손자녀 메시지·사진 확인
  ↓
음성으로 답장 (또는 정해진 문구·스티커 선택)
  ↓
오늘의 회상 활동 1~2개
  ↓
활동 내용이 가족에게 전달
```

**세션 길이 목표: 5~10분**

가족이 며칠 들어오지 못해도 서비스가 멈추지 않아야 한다. 새 문제가 없는 날은 이전 메시지 다시 보기 또는 기본 회상 활동부터 시작한다.

## 4. 기능 정의

### 4.1 회상 활동 (메인)
환자 개인의 생애 정보에서 생성되는 활동. 본 서비스의 정체성.

| 활동 | 입력 소재 예시 | 형태 |
| --- | --- | --- |
| 레시피 순서 맞히기 | "김치찌개를 잘 하셨다" | 재료·조리 순서 배열 |
| 옛 동네 이야기 | 젊을 때 살던 지역 | 사진 보고 자유 회상 |
| 노래 이어부르기 | 좋아하던 노래 | 몇 소절 듣고 이어 부르기 |
| 물건 용도 말하기 | 시대별 생활용품 | 사진 보고 설명 |
| 가족 사진 속 인물 짚기 | 가족 사진 | 인물 지목·이름 말하기 |

### 4.2 보조 인지 활동
범용 활동. 개인 소재가 부족한 날의 완충재 역할.
- 컵 속 공 찾기 (주의력)
- 미로 찾기 (시공간)

*크로스워드는 제외 — 초기·중기 환자에게 난이도와 문자 입력 부담이 크다.*

### 4.3 가족 연결
- 손자녀가 문제를 출제해 전송
- 문제 해결 후 메시지·사진 열람
- 환자의 **음성 답장** 또는 정해진 문구·스티커 선택 (타이핑 요구하지 않음)
- 활동 중 나온 이야기를 가족에게 요약 전달 → 다음 만남의 대화 소재로 활용

### 4.4 시설 공동 목표
클랜전 구조의 변형. **비동기 협력, 경쟁 없음.**

- 한 주 동안 같은 요양원 어르신들의 활동이 모여 공동 목표를 채움
- 상대는 다른 요양원이 아니라 **목표치 자체**
- 개인 순위·기여도는 비공개, 함께 채운 정도만 표시
- 목표 달성 시 "우리 요양원 기억 앨범"이 결과물로 남음

## 5. 설계 원칙

### 5.1 정답을 판정하지 않는다
회상 활동의 목적은 정답을 맞히는 것이 아니라 기억을 꺼내는 경험 자체다.
- 틀린 답에 오답 표시를 하지 않음
- "그럴 수도 있겠네요, 다른 이야기도 들려주세요" 식으로 이어감
- 점수·코인·랭킹 없음

### 5.2 경쟁 요소를 의도적으로 제외
인지 수준 차이가 눈에 보이면 뒤처진 사람이 위축된다. "틀려도 괜찮다"는 원칙과 정면으로 충돌하며, 시설 입장에서도 우리 어르신이 뒤처졌다는 결과는 판매 저항 요인이 된다.

### 5.3 정서적 안전
- 가족이 소재를 입력할 때 민감한 주제 여부를 표시
- 대화 중 부정적 반응이 감지되면 부드럽게 화제 전환
- 세션 후 가족에게 "오늘 어떤 이야기에서 반응이 좋았는지" 공유

### 5.4 AI 과의존 방지
독거·시설 거주 어르신은 대화 상대가 적어 의존이 빠르게 생긴다. 인지 저하가 있으면 AI와 사람을 구분하는 판단도 흐려진다. **앱이 잘 될수록 사람과의 접촉이 줄어드는 상황을 만들지 않는다.**

- AI가 사람에게 밀어내는 구조: "그 얘기 따님한테도 해보셨어요?"
- 하루 대화 분량에 자연스러운 마무리를 둠 ("내일 또 이야기해요")
- 사람인 척하는 연출을 피하고 AI임을 흐리지 않음
- 대화 빈도 급증·부정적 표현 지속 시 가족에게 알림

## 6. AI 활용

| 역할 | 내용 |
| --- | --- |
| 활동 생성 | 단편 정보를 활동으로 변환. "김치찌개를 잘 하셨다" → 레시피 순서 문제 |
| 대화 유지 | 음성 답변을 받아 맥락에 맞게 반응. 판정이 아닌 대화 지속이 목적 |
| 정서 감지 | 부정적 반응 감지 시 화제 전환 |
| 소재 확장 | 입력된 소재에서 연관 질문을 파생시켜 입력 부담 경감 |

**가족의 소재 입력 부담을 줄이는 것이 서비스 지속 가능성을 결정한다.** 매번 직접 문제를 만들어야 하면 며칠 만에 이탈한다.

## 7. 차별점

### 7.1 시판 인지 훈련 앱 대비
기존 앱은 **누구에게나 같은 문제**를 낸다. 환자 개인의 삶과 무관한 활동이므로 흥미가 오래가지 않는다. 본 서비스는 **그 사람의 생애에서 문제가 나온다.**

가족이 소재를 채워야만 작동하는 구조이므로, 경쟁사가 자본으로 즉시 복제할 수 없는 자산이 축적된다.

### 7.2 가족이 직접 하는 것 대비
대체가 아니라 보완이다.
- 매일은 불가능한 빈도를 메움
- 반복 질문에 지치지 않음 → 돌봄 가족의 소진 완화
- 반응이 좋았던 소재를 기록해 실제 만남에서 활용
- 나눈 이야기가 사라지지 않고 축적됨

### 7.3 시설 집단 회상 프로그램 대비
집단 프로그램은 공통 소재를 쓸 수밖에 없다. 개인화된 소재를 1:1로 제공하며, 인력 부담 없이 매일 운영 가능하다.

## 8. 수익 모델

| 단계 | 대상 | 내용 |
| --- | --- | --- |
| 1단계 | **요양시설 B2B** | 프로그램 도입 형태. 고객이 명확하고 1계약당 다수 사용자. 공동 목표 기능이 시설 프로그램 운영 실적과 직결 |
| 2단계 | **가족 구독** | 가정 돌봄 대상. 자녀가 결제하고 부모가 사용 |
| 3단계 | **공공 연계** | 치매안심센터 등. 검증 이후 단계로 상정 |

*공공 조달은 검증된 서비스가 아니면 진입이 어렵다. 초기 계획이 아닌 성장 계획으로 배치한다.*

---

## 9. 데이터 및 윤리

개인 생애사, 가족 관계, 건강 상태가 결합된 민감 정보를 다룬다.

- **동의 주체**: 환자 본인의 동의 능력이 온전하지 않을 수 있어 법정대리인·보호자 동의 절차를 명확히 규정
- **접근 권한**: 가족 중 누가, 요양보호사 중 누가 무엇을 볼 수 있는지 분리
- **투명성**: 어르신 본인이 자신의 기록이 가족과 공유된다는 사실을 아는 상태를 유지. 모르게 감시받는 구조는 신뢰를 깬다
- **보존 범위**: 민감한 대화 내용의 보관 기간과 공유 범위에 선을 그음

## 10. 개발 범위

### 10.1 대회 기간 내 구현 (3개월, 3인)
결선 요건은 **핵심 플레이 1개, 1스테이지, 3~5분 시연**이다. 범위를 좁게 잡는 것 자체가 심사 항목이다.

**핵심 플레이 1개 = 손자녀 문제 → 메시지 확인 → 맞춤 회상 활동 1개**

이 한 사이클에 서비스 정체성이 모두 담겨 있으며 3분 내 시연이 가능하다.

### 10.2 확장 계획 (대회 이후)
- 시설 공동 목표 기능
- 다른 지역 요양원과의 질문 교류
- 활동 종류 확대
- 요양보호사용 관리 도구
