# 디자인 요청 목록

외부(디자이너·생성 AI)에 맡길 항목. 2026.09.01 기준 코드에서 실제로 쓰이는 것만 추렸다.

## 0. 먼저 전달할 제약

무엇을 만들든 아래를 지켜야 한다. 요청할 때 이 블록을 함께 넘긴다.

```
[서비스] 초기·중기 치매 어르신용 회상 게임. 태블릿 가로 1280x800.
        1차 사용자는 어르신 본인이며 혼자 손가락으로 조작한다.

[반드시]
- 기본 글자 24px 이상, 버튼 안 글자 32px 이상
- 터치 영역 최소 100x100px, 버튼 사이 간격 넉넉히
- 흰 배경 + 진한 회색 글자, 명도 대비 크게 (본문 4.5:1, 테두리 3:1 이상)
- 화면당 누를 수 있는 요소 최대 4개
- 색으로만 정보를 전달하지 않기 (아이콘과 글자를 함께)
- 애니메이션은 느리고 부드럽게, 깜빡임·빠른 움직임 금지

[절대 금지]
- X 표시, 빨간색 경고, 오답 표시, 실패 화면
- 점수, 코인, 별점, 정답률, 랭킹, 연속 기록
- 순위·기여도 비교
- "한 번 더", "계속하기", "목표를 채우세요" 같은 유도 문구
- 치료·진단·인지 향상을 암시하는 표현

[기술 제약]
- 오프라인에서 전부 작동해야 한다. 외부 CDN에서 폰트·이미지를 불러올 수 없다
- 모든 파일은 프로젝트 안에 두는 로컬 파일이어야 한다
- 이미지는 SVG 우선(용량·확대), 사진풍이 필요하면 WebP

[인물]
- 실제 인물 사진을 쓰지 않는다. 모두 가상 인물이며 일러스트로 만든다
- 등장인물: 김순자(82세 여성, 본인) / 손녀 지민 / 손자 준호
```

## B. 아이콘 9개 — 우선순위 2

지금은 코드 안에 손으로 그린 인라인 SVG다. 굵기와 모양새가 제각각이다.
**하나의 세트로 통일된 선 아이콘**이 필요하다.

| 이름 | 뜻 | 크기 | 쓰이는 곳 |
| --- | --- | --- | --- |
| 마이크 | 말하기 | 112 | 누르고 있는 동안 녹음 버튼 |
| 말풍선 | 문제 풀기 | 96 | 마무리 화면 카드 |
| 냄비 | 레시피 활동 | 96 | 마무리 화면 카드 |
| 낱말 | 낱말 채우기 | 96 | 마무리 화면 카드 |
| 음표 | 노래 부르기 | 96 | 마무리 화면 카드 |
| 사진 | 사진 보고 이야기 | 96 | 마무리 화면 카드 |
| 사람들 | 사진 속 사람 찾기 | 96 | 마무리 화면 카드 |
| 컵 | 공 찾기 | 96 | 마무리 화면 카드 |
| 미로 | 길 따라가기 | 96 | 마무리 화면 카드 |

**조건**
- 선 아이콘, 선 굵기 통일 (지금은 5~6px 기준, 96 뷰박스)
- `stroke="currentColor"` — 색을 CSS에서 정하므로 아이콘 안에 색을 박지 않는다
- 채우기 없이 선만. 배경 도형 금지
- 멀리서도 무엇인지 알아볼 수 있을 만큼 단순하게

컵 아이콘은 하나 더 필요하다: **공 찾기 활동의 컵 본체**(160x200). 뚜껑이 위로 들리는 애니메이션이 있어 **컵 부분과 안의 공이 분리된 요소**여야 한다.

## C. 색과 글꼴 — 우선순위 3

### 지금 상태

무채색뿐이다. 브랜드 색이 하나도 없다.

```
--color-bg:        #ffffff   흰 배경
--color-text:      #1f2933   본문 (대비 15:1)
--color-text-soft: #45525e   보조 글자 (대비 8.4:1)
--color-border:    #6b7680   테두리 (대비 4.6:1)
--color-fill:      #1f2933   버튼 채움
--color-pressed:   #dfe3e7   눌렀을 때
--color-surround:  #e8ebee   화면 바깥
```

### 요청할 것

**포인트 색 1개.** 지금은 강조할 방법이 굵기와 채움뿐이다. 다만 **빨강 계열은 쓸 수 없다**(경고로 읽힌다). 초록·청록·따뜻한 갈색 계열이 후보다. 정한 색은 흰 배경에서 대비 4.5:1 이상이어야 한다.

**색을 바꿀 때 반드시 지킬 것**
- 어떤 색도 "맞음/틀림"을 뜻하게 쓰지 않는다
- 선택지 여러 개를 서로 다른 색으로 칠하지 않는다 (하나만 도드라지면 추천이 된다)

**글꼴.** 지금은 시스템 폰트만 쓴다(오프라인 요건). 전용 글꼴을 쓰려면 **파일을 프로젝트에 넣고 `@font-face`로 로컬 임베드**해야 한다. Google Fonts 링크는 쓸 수 없다.

- 한글 지원 필수
- 24px에서 읽히는 굵기, 획이 가늘지 않을 것
- 노안·백내장을 감안해 자간이 좁지 않을 것
- 본문용·제목용 두 굵기면 충분

## D. 아직 화면이 없는 것 — 우선순위 4

만들어야 하는데 아직 없다. 디자인부터 필요하다.

| 화면 | 상태 |
| --- | --- |
| 지난 이야기 보기 | 홈에 버튼만 있고 눌러도 아무 일이 없다 |
| 앱 아이콘 / 로고 | 없음 |
| 첫 화면(스플래시) | 없음 |
| 오프라인·오류 상태 | 없음. 어르신 화면에는 오류를 띄우지 않는 것이 원칙이라 "조용한 대체 화면"이 필요하다 |

## E. 가족용 화면 — 우선순위 5

**어르신용 기준(24px, 100px 터치, 화면당 4개)을 따르지 않는다.** 일반적인 모바일 앱 디자인으로 만든다.

현재 최소한의 스타일만 입혀 둔 상태다. 탭 4개로 되어 있다.

| 탭 | 내용 |
| --- | --- |
| 소재 | 생애 소재 입력(3단계) + 등록 목록 |
| 문제 내기 | 문제·선택지 3개·함께 보낼 말 |
| 오늘 이야기 | 활동 요약, 이야기가 잘 이어진 소재 |
| 우리 요양원 | 시설 공동 목표 진행 |

**여기서 지킬 것**
- 소재 입력은 한 번에 하나씩 묻는다. 긴 폼을 한 화면에 펼치지 않는다 (한 소재 30초 목표)
- 공동 목표에 개인별 순위·기여도를 표시하지 않는다
- "민감한 주제일 수 있음" 표시는 색만이 아니라 글자로도 알린다
